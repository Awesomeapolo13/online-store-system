# Создание заказа

## Описание

1) Создание заказа происходит через запрос `POST /api/v1/order`. Тело запроса ниже:
```json
{
  "user_id": 1,
  "region": 52
}
```

Правила валидации:
- все параметры обязательные;
- код региона - число, должен быть в `App\Order\Domain\Enum\RegionCodeEnum`.

2) Если не удалось найти корзину или в ней нет продуктов, то возвращаем ошибку с кодом 400 и текстом "В вашей корзину отсутствуют продукты для оформления заказа.".
3) Создание заказа происходит через отдельную команду `CreateOrderCommand`.
4) В процессе создания необходимо перенести данные в сущности Order и OrderItem. Установить заказу статус "Принят".
5) По итогу создания заказа установить корзине метку `deleted_at`, отправить команду на создание новой корзины и событие создание заказа.
6) Пользователю отдавать ответ 200.

## Требования

1) Cоздать таблицы `order_order` и `order_order_item` по аналогии с `order_cart` и `order_cart_item`. В таблицу `order_order` так же добавить:
   - ссылку на `status_id` из таблицы статусов заказов `order_status`;
   - фактическую стоимость заказа (`actual_total_cost`).
2) В таблицу `order_order_item` дополнительно добавить поля:
   - `actual_total_cost`;
   - `actual_quantity`.
3) Создать таблицу `order_status`:
   - числовой первичный ключ;
   - `status_id` - число;
   - заголовок статуса;
   - строковый код статуса типа (`accepted`, `preparing` и прочих);
   - логическое поле `is_delivery`.
4) Заполнить таблицу статусов записями статусов (`status_id`, `title`, `code`, `is_delivery`):
   - 0, Принят, accepted, false;
   - 0, Принят, accepted, true;
   - 1, Собираем, preparing, false;
   - 1, Собираем, preparing, true;
   - 2, Готов, ready, false;
   - 2, Передан в доставку, delivery, true;
   - 3, Выдан, finished, false;
   - 3, Получен, finished, true.
5) Связь между таблицей заказа и статуса осуществляется по status_id + is_delivery.

Создание всех таблиц осуществлять через механизм Doctrine. Т.е. сначала составить файлы маппингов `orm.xml`, затем попросить доктрину создать миграции.
Поля `actual_total_cost` и `actual_quantity` при создании заказа должны быть равны полной стоимости и количеству товара. Они будут в дальнейшем меняться при обновлении заказа (например если не будет нужного количества товара на складе).

Добавление событий осуществлять через метод `recordEvent`. Отправку событий осуществлять через метод `releaseEvents`. Обработку события создания заказа осуществлять асинхронно, через отдельную очередь.
Класс обработчик пока не создавать.
